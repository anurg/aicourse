LangChain is a toolkit for building apps that use **AI language models (LLMs)** like OpenAI, Anthropic, etc. Think of it like **plumbing + LEGO pieces** that help you connect:

- a chat model (the “brain”)
- your data (files, databases, websites)
- tools (search, calculators, APIs)
- memory (conversation history / user context)
- workflows (multi-step processes)

So instead of writing all the glue code yourself, LangChain gives you common building blocks.

## What problems LangChain solves
On its own, an LLM:
- answers based on what it was trained on
- can’t reliably access your private documents
- doesn’t “execute” real actions unless you connect it to tools
- can lose context if conversations get long

LangChain helps you build systems where the model can:
1. **Fetch info** from your sources (documents, DBs)
2. **Use tools** (call APIs, run functions)
3. **Follow steps** (chains/agents)
4. **Keep track** of context (memory/state)

## Core ideas (simple definitions)

### 1) Chains (step-by-step workflows)
A **chain** is a sequence of steps, like:
- take user question → create a prompt → call the model → format the answer

Example: “Summarize this text” is a simple chain.

### 2) Retrieval-Augmented Generation (RAG)
RAG means: **look up relevant documents first**, then have the LLM answer using those.

Typical flow:
- Your docs are split into chunks
- Converted into embeddings (number vectors)
- Stored in a vector database
- When a question comes in, it retrieves the closest chunks
- The LLM uses those chunks to answer

This is how you build “Chat with my PDFs / knowledge base” apps.

### 3) Agents (the model chooses actions)
An **agent** is when the LLM can decide:
- “I should search”
- “I should call this API”
- “I should calculate”
…and then it does those actions and uses the results.

Good for tasks like travel planning, IT support triage, data lookup, etc.

### 4) Tools (actions the LLM can take)
A **tool** is a function or API you expose, like:
- `search_web(query)`
- `get_customer_account(id)`
- `create_ticket(summary)`
LangChain helps define and call these in a structured way.

### 5) Memory / State (keeping context)
LangChain provides patterns to store conversation history and important facts (though in modern setups, people often use more explicit “state” plus summarization).

## What you build with LangChain (examples)
- Internal helpdesk chatbot that answers from company docs (RAG)
- Customer support assistant that can check order status (tools + agent)
- Document summarizer / contract review assistant (chains + RAG)
- Multi-step workflows: “ingest docs → index → Q&A → citation output”

## LangChain vs LangGraph (quick clarity)
- **LangChain**: the general library of components (models, prompts, retrievers, tools).
- **LangGraph** (from the same ecosystem): for building **more reliable, stateful, multi-step agent workflows** (like a flowchart with loops and checkpoints). Many people now use LangGraph for complex agent behavior.

## When LangChain is a good choice
Use it if you want:
- faster setup for RAG and tool-using assistants
- lots of integrations (vector DBs, loaders, model providers)
- a standard framework rather than custom glue code

## When you might not need it
If your app is simple (just “send prompt → get response”), you can call the model API directly without a framework.
